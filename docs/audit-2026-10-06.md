# SSO audit and upgrade acceptance — 2026-10-06

Reviewed baseline: `1f95e112dc9b12cb37516d0af6014994821f2ec6`. This is a
repository/configuration audit, with real Heimdall and OAuth2 Proxy binary tests.
It is not evidence that a deployed Cilium datapath or live Authentik directory has
the same configuration. No production login, credential, database or user was read.

## Changes in this branch

- OAuth2 Proxy `v7.15.4` → `v7.15.5`, Heimdall `0.17.22` → `0.17.23`, and
  unprivileged Nginx `1.30.5-alpine` → current mainline `1.31.6-alpine`.
- SSO foundation resources now prune revoked policies. The `sso` and `cert-manager`
  Namespaces explicitly opt out of pruning, and deletion of the foundation
  Kustomization still orphans its resources.
- A namespace-wide default-deny **ingress** NetworkPolicy remains after removal of
  a per-service Cilium allow policy. Egress is unchanged. Host-network DNS requires
  separate firewall protection.
- CI renders all pinned Helm charts and validates native/custom resources against
  their schemas. It also checks public path exceptions, route authorization,
  callback/SAN coverage, administrator groups and credential retention. Actions
  are updated to immutable commit refs and do not persist checkout credentials.

Authentik `2026.8.3`, cert-manager `v1.21.2`, CoreDNS `1.14.7`, and the secret
generator `3.4.1` are already at their verified latest releases. PostgreSQL stays
on the current 17.x patch (`17.11-standard-trixie`). PostgreSQL 18.6 is a separate
data migration requiring backup/restore testing, not a routine image replacement.
Gateway API schemas are tested against the companion repository's v1.6.2
experimental bundle; preserve that channel because ExternalAuth is experimental.

## Trust boundaries reviewed

| Boundary | Evidence and conclusion |
| --- | --- |
| Client → Gateway | Exact route hostnames, HTTPS termination, HTTP redirect, explicit certificate SANs and same-namespace route admission. Unknown hosts have no application route. Write access to `sso` HTTPRoutes can still publish a bypass; namespace RBAC and Git write permissions are security boundaries. |
| Gateway → Heimdall | Protected application rules use native GRPC ExternalAuth. No forwarding of application request bodies. Cookies, Authorization and Accept are the explicit auth inputs. Cilium's fail-closed behavior still needs a real outage test. |
| Heimdall → identity service | The generic authenticator obtains identity/group data from OAuth2 Proxy, with no identity cache. Tests reject forged group headers, missing/malformed groups and unknown hosts. The internal hop is plaintext and trusts the cluster/node boundary. |
| OAuth2 Proxy → Authentik | Verified OIDC issuer, TLS CA, audience/signature checks, S256 PKCE, strict callbacks and explicit redirect host allowlist. No password grant, skip-auth regex or client-IP exemption is configured. |
| Browser cookie | `__Host-` prefix, Secure, HttpOnly, path `/`, no Domain and a five-minute lifetime. Generated AES key is 32 random bytes encoded URL-safe Base64. A cookie is host-specific; a new service needs its own callback registration. |
| Authorization | `sso-users` admits the ordinary portal. Admin hosts use an empty ordinary-service group. `cluster-admins` and upstream `authentik Admins` intentionally admit every registered protected service. Native Authentik RBAC remains necessary on shared APIs. |
| Public IdP paths | Login/flow executor, OIDC, static assets, selected bootstrap APIs and `/oauth2/` must work before a gateway session exists. They terminate at the IdP/proxy, not at a protected application. CI now inventories those exceptions. `/if/admin` redirects on the ordinary host; the API still relies on native Authentik permissions. |
| Backend access | Cilium policies admit expected Gateway, Authentik and CNPG callers. Direct Pod-IP/ClusterIP paths do not run HTTPRoute auth. New default-deny ingress protects otherwise unselected pod endpoints; validate real identities and probes before rollout. |
| Kubernetes credentials | Authentik server/worker, proxy, Heimdall, DNS and static pages do not mount service-account tokens. The rendered generator uses a Role/RoleBinding in `sso`, with no ClusterRole. cert-manager and CNPG have controller privileges by design. |
| Secret lifecycle | Git contains generated-secret declarations and references, not credential values. `IfNotPresent` prevents Flux from replacing populated generated Secrets; prune exclusions retain them. Database and CA recovery must preserve the corresponding keys. |

## Findings requiring attention

| ID | Priority | Finding | Required follow-up |
| --- | --- | --- | --- |
| SSO-01 | High, fixed | At baseline, deleting a policy from Git did not delete it in Kubernetes. Removing the final pod-selecting policy manually could also restore default-allow behavior. | This branch couples pruning with namespace retention and a deny baseline. Test removal of a temporary allow policy in a disposable/staging environment; access must stop and namespaces must remain. |
| SSO-02 | High, updated | OAuth2 Proxy 7.15.5 fixes security defects present before that release. The upstream path/client-IP bypasses require options not used here; no successful exploit of this configuration was demonstrated. | Deploy the patch after the acceptance checks. Review logging retention if callback errors may have contained credentials. |
| SSO-03 | High, open | `main` is unprotected and has no ruleset. It is an automatically reconciled privileged source. | Require review and successful checks; protect auth rules, public-route exceptions, network policies, blueprints and workflows. Choose actual maintainers for CODEOWNERS. |
| SSO-04 | High, open | One database instance on a one-replica volume; no independent backups. Retention annotations do not prevent disk loss or PVC deletion. | Back up PostgreSQL, `sso-credentials`, `oauth2-cookie`, the CA key and any later file storage off-cluster; demonstrate restore. Decide RPO/RTO and replication needs. |
| SSO-05 | High, open | Administrator MFA is not enforced by this repository. The bootstrap account and both administrator groups have broad authority. | Inspect live default flows, enforce MFA, verify break-glass recovery, rotate the bootstrap password, and audit administrator membership and service-account scopes. Do not grant `cluster-admins` merely to fix access to one application. |
| SSO-06 | Medium, open | DNS binds every node's IP on port 53, forwards to public resolvers, and uses host networking. Pod NetworkPolicy does not provide its LAN access control. | Restrict TCP/UDP 53 to intended LAN/VPN sources; verify no Internet exposure and select approved recursive resolvers. Check for host-port conflicts. |
| SSO-07 | Medium, open | Heimdall's ext_authz and identity calls are plaintext; Cilium policies allow host/remote-node identities where Envoy needs them. Egress is unrestricted. | Decide whether nodes/LAN are trusted; implement tested transport encryption and egress rules if required. A compromised node is not contained by these pod policies. |
| SSO-08 | Medium, open | Authentik and the generator's rendered containers do not explicitly deny privilege escalation, drop capabilities or set seccomp. The namespace also contains host-network DNS. | Test chart-supported container restrictions; separate host-network infrastructure if enforcing a restricted Pod Security profile. Do not invent a container UID or force read-only storage without startup testing. |
| SSO-09 | Medium, open | Single replicas and hard-coded first-node `API_IP` make SSO unavailable during node loss/maintenance. Replicas alone cannot fix the database or address dependency. | Provide a stable Gateway endpoint, replicated state, disruption planning and capacity before claiming HA. |
| SSO-10 | Medium, open | Secret values passed as environment variables are only read at process startup. Changing a Secret does not itself restart these Deployments or synchronize Authentik's stored provider secret. | Plan and test coordinated OIDC/cookie/bootstrap/CA rotation. For OIDC secrets, update/reload Authentik's blueprint worker and restart the proxy in the intended order. Cookie-key rotation deliberately logs users out. |
| SSO-11 | Medium, conditional | No `/data` volume or S3 file backend is configured. Modern Authentik disables uploads without appropriate file storage. Its current file URLs use `/files/`, while the legacy public exception is `/media/`. | If enabling uploaded icons, backgrounds or reports, configure persistent/shared storage and review the signed-file route separately. Do not expose all `/files/` URLs without checking access to reports. No file-storage migration is performed here. |
| SSO-12 | Medium, open | CI's browser-auth test runs real Heimdall against synthetic identity responses. It does not run Authentik, OAuth2 Proxy login, Cilium routing and a browser together. | Complete the end-to-end acceptance matrix below. CI green is not proof of a complete OIDC login flow or datapath isolation. |

Five-minute stale cookie/JWT claims after membership changes are an explicit current
contract, not immediate revocation. IdP logout alone does not revoke every gateway
cookie. If emergency revocation must be immediate, design a session/introspection
mechanism and a tested emergency response; do not describe the current setup as one.

Authentik's [current architecture](https://docs.goauthentik.io/core/architecture)
and [2025.12 storage changes](https://docs.goauthentik.io/releases/2025.12/) explain
the file-storage limitation. Its [2026.8 release notes](https://docs.goauthentik.io/releases/2026.8/)
also require correct trusted-proxy networks for forwarded headers. Verify the live
Gateway source addresses are trusted as intended; do not broaden trust to `0.0.0.0/0`.

## Validation and acceptance

Local checks passed: 112 strict schema validations with no skipped schemas,
declarative security invariants, the exact OAuth2 Proxy 7.15.5 cookie validator,
and Heimdall 0.17.23 projected-volume startup and gRPC authorization tests.
The Nginx image tag was verified for amd64 and arm64. The exact Nginx container,
upstream Heimdall rule validator and other Docker tests are CI checks; inspect the
actual PR results. No live Cilium or Authentik-browser test was run locally.

Run these checks against a staging cluster, then after the maintenance rollout:

| Scenario | Required result |
| --- | --- |
| Fresh browser on `auth.internal/` | Login form and assets load before a gateway session exists; no redirect loop |
| `akadmin` / enrolled administrator | Admin UI and its native API work after authentication; MFA policy is exercised |
| Ordinary `sso-users` member | Portal works; admin host is denied even with a forged identity/group header |
| No group or unrelated service group | Browser receives the denial page; API receives 403 |
| Missing, invalid or expired credentials | Browser login redirect or API 401; backend never receives a protected request |
| Invalid bearer plus a valid cookie | Invalid bearer must not become an authenticated API request via cookie fallback |
| Bad issuer/audience/signature/expiry JWT | Denied by the real OAuth2 Proxy; synthetic identity tests do not prove JWT verification |
| Unknown host / unregistered callback / redirect destination | No application route or accepted OAuth callback/open redirect |
| Public path encodings, duplicate slashes and dot segments | No access to native admin APIs without native permission or to a protected application |
| Heimdall or identity lookup unavailable | Protected request fails closed; no authenticated response from the backend |
| Direct Pod-IP/ClusterIP call from unrelated namespace | Blocked for Authentik, PostgreSQL, Heimdall and OAuth2 Proxy |
| Default deny with actual Cilium identities | Required ext_authz, OIDC, DB, operator and kubelet probes remain functional |
| Revoked temporary allow policy | Flux removes it; deny baseline remains; namespaces and stored secrets remain |
| Secret/certificate renewal and rotation | Correct rollout/order, valid TLS and expected session invalidation |
| Loss of first node / database node | Observed behavior matches the agreed availability and recovery plan |

Before merging, ensure companion Flux/Gateway and storage changes are healthy,
all route conditions match their current generation, backups are recoverable and
console/cluster-admin recovery remains available. The branch does not enable MFA,
create backup credentials, choose LAN firewall CIDRs or modify the live directory.
